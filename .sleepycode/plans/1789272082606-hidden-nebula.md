# Fix conversation-context loss while chatting

## Problem (verified)

Chat history is silently and permanently dropped in several places. Confirmed by reading the code:

| # | Location | Trigger | Visible | Reversible |
|---|---|---|---|---|
| 1 | `src/agent.ts:2494`, `:2545` `conversation.items = conversation.items.slice(-60)` | 61st item | ❌ silent | ❌ permanent |
| 2 | `src/agent.ts:2308` `conversation.items.slice(-10, -1)` | every non-resume turn | ❌ silent | model-only |
| 3 | `src/agent.ts:747`/`:752` `projects.slice(0,60)` / `conversations.slice(0,100)` | save | ❌ silent | ❌ permanent |
| 4 | compaction undo — `src/agent.ts:2668-2669` "in-memory … does not survive an extension reload", redo capped `redo.slice(-3)` (:2678) | reload | ⚠️ divider shown | ⚠️ memory-only |
| 5 | `src/util.ts:130` `truncate()` → `MAX_TOOL_OUTPUT` 40k | tool output > 40k | ✅ marker | ❌ |

The **60-item cap (#1) is the real bug** — it silently discards turns from both scrollback and storage. The others are by-design or already surfaced but still worth hardening, per the chosen scope.

## Goal

Nothing is lost silently. History persists; what the *model* sees is explicitly budgeted and (optionally) surfaced.

## Design

### Fix 1 — stop the silent 60-item cap (primary)
`src/agent.ts` (2 sites: ~2494 success path, ~2545 error path)
- Replace `conversation.items = conversation.items.slice(-60)` with a **large safety bound** (e.g. `MAX_STORED_ITEMS = 2000`) applied only as a hard guard against unbounded memory — not a routine trim.
- No routine dropping at 60. Scrollback and persisted history both keep the full conversation.
- Add constant in `src/types.ts`: `export const MAX_STORED_ITEMS = 2000;`

### Fix 2 — token-budgeted model window (replace the hard 10-item slice)
`src/agent.ts:2308`
- Replace `conversation.items.slice(-10, -1)` with a helper that walks backwards accumulating `estimateContextTokens`-style chars/4 cost until a budget is hit (reuse `CHARS_PER_TOKEN`, `COMPACTION_HISTORY_ITEMS` as a *floor*, context window from the active provider group).
- New helper `private recentContextItems(conversation, budgetTokens): TranscriptItem[]` that keeps the newest items fitting the budget (min `COMPACTION_HISTORY_ITEMS`) — so short convos send everything and long ones send as much as fits, instead of always 9.
- Keep the `kind !== 'divider'` filter.

### Fix 3 — persistence caps
`src/agent.ts:746-758` `persistProjects`
- Raise project cap `60 → 500` and conversations-per-project `100 → 500` (constants in `types.ts`).
- Guard: if a project's serialized conversations exceed a sane byte budget, keep newest and emit the Fix 5 notice rather than dropping silently.
- Keep writing the index for all retained projects.

### Fix 4 — durable compaction undo
`src/agent.ts` (`compactionUndoStacks`/`compactionRedoStacks` ~2671-2700, fields near :150)
- Persist compaction snapshots to `globalState` key `sleepycode.compactionSnapshots.<conversationId>` (bounded to last 3).
- On load (in the conversation-load path) hydrate the in-memory stacks from globalState so undo survives reload.
- Clear on conversation delete / reset.
- Update the stale comment at 2668-2669.

### Fix 5 — user-visible notices (no silent loss)
- Add a `WebMessage` `{ type: 'contextNotice'; conversationId: string; kind: 'trimmed'|'compacted'; text: string }` in `src/types.ts`.
- Post it whenever: the safety bound (Fix 1) actually trims, persistence drops data (Fix 3), or compaction runs (complement the existing divider).
- Render in `src/webview/runtime.ts` as a small inline system note in the transcript + a `src/webview/styles.ts` rule.

## Risks / edge cases
- **Memory**: removing the 60 cap means long conversations grow in RAM and in `globalState`. The 2000-item guard + the token-budget model window bound cost; verify a 500-turn conversation still loads.
- **`globalState` size**: VS Code state has practical size limits; Fix 3's byte guard + notice must trigger before a write would be rejected.
- **Compaction snapshot shape**: confirm the exact `{ before, after }` fields (agent.ts:2674/2679) before persisting — reuse the same shape, JSON-serializable `TranscriptItem[]`.
- **Existing tests** assert raw file source (`test/sleepycode-regressions.test.mjs`), so line changes to `agent.ts` can break regex assertions — run `npm test` and fix pinned expectations.
- Migration: conversations already trimmed to 60 cannot be recovered; the fix is forward-only.
